Q.equals()와 hashCode()의 차이는 무엇이며, 왜 두 메서드를 함께 재정의(Override)해야 하나요?

🎯 면접관의 의도

자바 객체의 동등성(Equality) 비교 원리와 HashSet, HashMap 등 컬렉션 프레임워크가 내부적으로 객체를 찾는 방식을 매커니즘 수준에서 이해하는지 평가합니다.

✅ 모범 답변 가이드

1. 두 메서드의 역할:
equals()는 두 객체의 내용(값)이 논리적으로 같은지 비교하고, hashCode()는 객체를 식별하는 정수형 해시 코드 값을 반환합니다.

2. 함께 재정의해야 하는 이유 (HashMap/HashSet 동작 원리):
HashSet이나 HashMap은 객체를 저장하거나 찾을 때 먼저 hashCode()를 비교하여 해시 버킷 위치를 찾습니다. 해시 값이 같을 때에만 비로소 equals()를 호출해 최종 동등 여부를 판가름합니다.

만약 equals()만 재정의하고 hashCode()를 재정의하지 않으면, 동등한 객체라도 서로 다른 해시 코드를 갖게 되어 HashMap에서 객체를 찾지 못하거나 중복 저장되는 치명적인 오류가 발생합니다.

Q.JVM의 런타임 메모리 영역 중 스택(Stack)과 힙(Heap) 영역의 차이를 설명하고, 인스턴스 변수와 지역 변수가 각각 어디에 저장되는지 말씀해 주세요.

🎯 면접관의 의도

실제 수강생 후기에도 등장한 질문입니다. 멀티스레드 환경에서의 데이터 공유 여부와 메모리 관리 영역(GC 대상 여부)을 구분할 수 있는지 검증합니다.

✅ 모범 답변 가이드

1. 스택(Stack) 영역:
메서드 호출 시 스레드마다 독립적으로 생성됩니다. 지역 변수(Local Variable)와 매개변수가 저장되며, 메서드가 종료되면 스택 프레임과 함께 즉시 소멸합니다. 스레드 간 공유되지 않아 Thread-safe 합니다.

2. 힙(Heap) 영역:
new 키워드로 생성된 동적 객체(인스턴스)와 그 안에 속한 인스턴스 변수(Field)가 저장됩니다. 모든 스레드가 공유하는 영역이며, GC(Garbage Collector)의 관리 대상이 됩니다.

Q.Java 8에서 추가된 Stream API의 특징과 장점은 무엇인가요? 기존 for-loop와 비교하여 설명해 주세요.

🎯 면접관의 의도

모던 자바(Java 8+) 문법을 적극적으로 활용할 수 있는지, 함수형 프로그래밍 스타일의 가독성과 병렬 처리(Parallel Stream) 가능성을 파악하고 있는지 묻습니다.

✅ 모범 답변 가이드

1. 가독성과 선언형 코드:
기존 for문(외부 반복)은 데이터를 어떻게 가져올지 절차를 직접 구현해야 하지만, Stream API(내부 반복)는 "무엇을 수행할지" 선언형으로 작성하여 filter, map, collect 등으로 코드가 대폭 단축되고 가독성이 향상됩니다.

2. 지연 연산 (Lazy Evaluation):
스트림은 중간 연산(filter, map 등)을 즉시 실행하지 않고 쌓아두었다가, 최종 연산(collect, count 등)이 호출되는 시점에 한 번에 최적화하여 처리하므로 불필요한 계산을 줄입니다.

3. 병렬 처리 유용성:
parallelStream()을 활용하면 복잡한 멀티스레드 코드 구현 없이도 대용량 데이터를 손쉽게 병렬 처리할 수 있습니다.
#Java8 #StreamAPI #지연연산

Q.Optional이란 무엇이며, 왜 사용하나요? 올바른 사용 가이드라인도 함께 말씀해 주세요.

🎯 면접관의 의도

실무에서 자주 발생하는 NullPointerException(NPE)을 방지하는 방 방식을 이해하고, `Optional`을 오남용하지 않고 적재적소에 쓰는지 체크합니다.

✅ 모범 답변 가이드

1. 도입 목적:
Optional<T>는 "값이 존재할 수도 있고, 없을 수도 있는(null)" 데이터를 감싸는 래퍼 클래스입니다. 명시적으로 null 가능성을 표현하여 NullPointerException을 방지하고, orElseGet(), orElseThrow() 등을 통해 안전한 예외 처리를 돕습니다.

2. 실무 사용 주의사항 (안티패턴 방지):
Optional은 주로 '메서드의 반환 타입'으로만 사용하는 것이 권장됩니다. 생성자 매개변수나 클래스의 필드로 사용하면 오버헤드가 발생하므로 지양해야 하며, get() 메서드를 직접 호출하기보다는 null일 경우의 대체 동작을 정의하는 코드를 작성하는 것이 좋습니다.

Q.Java는 Call by Value인가요, Call by Reference인가요? 객체를 파라미터로 넘길 때의 동작 방식으로 설명해 주세요.

🎯 면접관의 의도

기술 면접 단골 함정 질문입니다. 자바의 파라미터 전달 방식에 대한 오해를 바로잡고 있는지, 참조 변수가 메모리 주소 '값'을 복사해서 전달한다는 사실을 명확히 아는지 봅니다.

✅ 모범 답변 가이드

Java는 무조건 Call by Value(값에 의한 호출)로만 동작합니다.

  • 원시 타입(Primitive Type): 변수가 가진 실제 값 자체가 복사되어 메서드로 전달됩니다.
  • 참조 타입(Reference Type / 객체): 객체의 실제 주소로 직접 연결되는 것이 아니라, '객체를 가리키는 메모리 주소값'이 복사되어 전달됩니다.
메서드 내부에서 전달받은 객체의 필드 값을 변경하면 원본 객체도 변경되지만, 메서드 내부에서 객체 자체에 new로 새 객체를 할당하더라도 원본 참조 변수는 바라보는 주소가 바뀌지 않습니다. 이것이 바로 Call by Value의 증거입니다.
#CallByValue #파라미터전달 #메모리주소복사

Q.스레드 안전(Thread-safe)하다는 것의 의미와, Java에서 멀티스레드 동기화를 구현하는 방법들에 대해 설명해 주세요.

🎯 면접관의 의도

백엔드 서버 환경(Spring)은 기본적으로 멀티스레드 환경입니다. 동시성 이슈(Race Condition)를 인지하고 이를 제어할 줄 아는지 평가합니다.

✅ 모범 답변 가이드

1. Thread-safe의 의미:
여러 스레드가 동시에 어떤 클래스나 객체에 접근하여 실행하더라도, 의도한 대로 정확하게 동작하고 데이터의 일관성이 깨지지 않는 상태를 말합니다.

2. 동기화 구현 방법:
  • synchronized 키워드: 메서드나 블록에 락(Lock)을 걸어 한 번에 하나의 스레드만 접근하도록 제어합니다. (단, 과도한 사용 시 성능 저하)
  • ConcurrentHashMap / AtomicInteger: 전체 락을 걸지 않고, 분할 락(Lock Striping)이나 CAS(Compare-And-Swap) 알고리즘을 사용해 성능 손실 없이 동시성을 보장합니다.
  • 불변 객체(Immutable Object) 활용: 상태를 변경할 수 없게 설계하여 동기화 없이도 근본적인 Thread-safe를 달성합니다.
#ThreadSafe #동시성이슈 #Synchronized

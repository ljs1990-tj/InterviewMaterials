순수 자바스크립트의 난해한 동작 원리를 통제하고, 정적 타입(TypeScript)의 이점을 논리적으로 설명하세요.

Q.(기출) 프론트엔드에서 서버와 통신할 때 주로 사용하는 GET 방식과 POST 방식의 차이점은 무엇인가요?

🎯 면접관의 의도

HTTP 프로토콜의 기본 규약과 REST API 설계 원칙을 이해하고 프론트엔드(fetch/axios)에서 목적에 맞게 API를 호출할 수 있는지 평가합니다.

✅ 모범 답변 가이드

가장 큰 차이는 '데이터 전송 위치'와 '사용 목적'입니다.
  • GET (조회용): 데이터를 서버로부터 읽어올 때 사용합니다. 전송할 데이터가 URL의 뒤에 쿼리 파라미터(?id=123)로 노출되어 전송됩니다. 캐싱(Caching)이 가능하여 브라우저에 저장될 수 있지만, 보안에 취약하고 길이 제한이 있습니다.
  • POST (생성용): 새로운 데이터를 서버에 생성하거나 수정할 때 사용합니다. 데이터가 HTTP Body(본문)에 숨겨져서 전송되므로 URL에 노출되지 않으며, 대용량 데이터를 안전하게 보낼 수 있습니다. (캐싱 불가)
#GET_POST #HTTP메서드 #REST_API

Q.(기출) 동기식 코드와 비동기식 코드를 함께 사용할 때 주의해야 할 점은 무엇이며, 어떻게 해결하나요?

🎯 면접관의 의도

API 통신 후 화면을 그리는 과정에서 비동기 타이밍을 제어하지 못해 발생하는 '경쟁 상태(Race Condition)'를 겪어보고 해결할 줄 아는지 실무 역량을 묻습니다.

✅ 모범 답변 가이드

비동기 코드는 실행 완료를 기다리지 않고 바로 다음 동기 코드로 넘어가버리는 특성이 있습니다.

따라서 서버에서 데이터를 받아오는 비동기 작업이 끝나기도 전에, 아래에 있는 동기 코드가 해당 데이터를 화면에 그리려고 시도하면 undefined 오류나 빈 화면이 렌더링되는 문제가 발생합니다.

이를 해결하기 위해 async/await를 사용하여 비동기 통신이 완료될 때까지 코드의 실행을 명시적으로 대기시키고, 데이터가 로딩 중일 때는 로딩 스피너(Loading State)를 띄워 오류를 방어해야 합니다.
#비동기제어 #RaceCondition #Async_Await

Q.자바스크립트의 클로저(Closure)란 무엇이며, 실무에서 어떤 경우에 활용되나요?

🎯 면접관의 의도

JS의 렉시컬 환경(Lexical Environment)과 가비지 컬렉션의 동작을 완벽히 이해하고 있는지 확인하는 고난도 단골 질문입니다.

✅ 모범 답변 가이드

클로저는 "함수가 선언될 당시의 외부 환경(변수)을 기억하여, 외부 함수가 실행이 종료된 후에도 내부 함수가 그 외부 변수에 계속 접근할 수 있는 현상"을 말합니다.

외부 함수의 실행이 끝나면 원래는 내부 변수들이 가비지 컬렉터에 의해 소멸해야 하지만, 내부 함수가 이를 참조하고 있으면 소멸하지 않습니다.
실무에서는 자바의 private 변수처럼 상태(데이터)를 외부에서 함부로 조작하지 못하게 안전하게 은닉화(캡슐화)할 때 주로 사용되며, 검색창의 디바운싱(Debouncing) 기능을 구현할 때도 핵심 원리로 쓰입니다.
#클로저 #Closure #정보은닉

Q.자바스크립트에서 객체의 얕은 복사(Shallow Copy)와 깊은 복사(Deep Copy)의 차이점은 무엇인가요?

🎯 면접관의 의도

참조 타입(객체, 배열)이 메모리에서 주소값을 복사(Call by Reference)한다는 것을 알고, 불변성을 유지하며 코드를 짤 수 있는지 평가합니다.

✅ 모범 답변 가이드

  • 얕은 복사: 객체의 가장 바깥 껍데기만 복사하고, 내부에 있는 중첩 객체는 '메모리 주소'만 복사합니다. (예: Spread 연산자 ...). 그래서 복사본의 내부 객체를 수정하면 원본 객체까지 훼손되는 버그가 발생할 수 있습니다.
  • 깊은 복사: 내부 중첩 객체까지 아예 새로운 메모리 공간에 재귀적으로 똑같이 복제하여 원본과 완벽히 분리하는 것입니다. 최신 브라우저의 structuredClone() 함수나 JSON.parse(JSON.stringify(obj)) 방식을 통해 원본의 불변성을 지킬 수 있습니다.
#얕은복사 #깊은복사 #불변성

Q.최근 많은 프로젝트에서 자바스크립트 대신 타입스크립트(TypeScript)를 도입하고 있습니다. 본인이 생각하는 그 이유는 무엇인가요?

🎯 면접관의 의도

런타임 언어와 컴파일 언어의 차이점을 명확히 알고, 정적 타입 지정이 대규모 협업과 유지보수 단계에서 주는 '안정성'의 이점을 논리적으로 설명할 수 있는지 확인합니다.

✅ 모범 답변 가이드

가장 큰 이유는 '런타임 에러 방지'와 '생산성' 때문입니다.

자바스크립트는 동적 타입(Dynamic Typed) 언어라, 오타가 나거나 잘못된 타입의 데이터를 넘겨도 브라우저에서 코드가 실행(Runtime)되고 나서야 에러가 터집니다. 이는 운영 서비스에서 매우 치명적입니다.

반면 타입스크립트는 JS에 타입을 명시적으로 부여한 정적 타입(Static Typed) 언어입니다. 코드를 치는 순간 IDE에서 에러를 띄워주거나, 빌드(컴파일) 과정에서 타입 에러를 100% 잡아주어 서비스 안정성이 획기적으로 올라갑니다. 또한, 객체 구조를 미리 알 수 있어 에디터의 자동완성(IntelliSense) 기능이 극대화되어 협업 효율이 매우 좋아집니다.
#TypeScript #정적타입 #런타임에러방지

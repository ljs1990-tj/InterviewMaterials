🔒 Part 1. 인증/인가 및 보안 기본기

Q.인증(Authentication)과 인가(Authorization)의 차이가 무엇인가요?

🎯 면접관의 의도

보안의 가장 기초가 되는 두 개념을 명확히 구분할 수 있는지 묻는 질문입니다. 프로젝트의 로그인/권한 처리 로직과 연관 지어 대답해야 합니다.

✅ 모범 답변 가이드

"인증(Authentication)은 사이트에 접근하는 사용자가 '누구인지(Who)'를 확인하는 과정입니다. 아이디와 비밀번호를 입력하여 로그인하는 행위가 이에 해당합니다."

"인가(Authorization)는 인증된 사용자가 특정 자원에 접근할 '권한(Permission)'이 있는지 확인하는 과정입니다. 예를 들어, 일반 유저로 로그인(인증)을 했더라도, 관리자 전용 페이지에는 접근하지 못하도록 막는(인가 실패) 것이 그 예입니다."

Q.JWT(JSON Web Token)에 대해 설명해 주세요. 세션 대신 이걸 쓴 이유가 있나요?

🎯 면접관의 의도

JWT의 구조(Header, Payload, Signature)를 아는지, 그리고 토큰 기반 인증이 가지는 '무상태성(Stateless)'의 이점을 이해하고 있는지 검증합니다.

✅ 모범 답변 가이드

"JWT는 JSON 객체를 사용하여 정보를 안전하게 가공하고 전달하는 웹 표준 토큰입니다. Header(타입/알고리즘), Payload(유저 정보), Signature(서명)로 구성되어 데이터의 위변조를 방지합니다."

"세션 대신 JWT를 사용한 이유는 서버의 확장성(Scalability) 때문입니다. 세션은 유저의 상태를 서버 메모리에 저장해야 하므로 트래픽이 많아지면 서버 부하가 심해집니다. 반면 JWT는 토큰 자체에 유저 정보를 담고 있어 서버가 상태를 유지할 필요가 없는 무상태(Stateless) 아키텍처를 구현할 수 있어 효율적입니다."

🛠️ Part 2. 기술 스택 선정 및 예외 상황 대처

Q.팀 프로젝트는 Spring Boot로 했는데, 굳이 개인 프로젝트에서 React와 Express를 사용한 이유가 있나요?

🎯 면접관의 의도

다양한 스택을 써본 것은 좋으나, "그냥 유행해서", "배워서"라는 수동적인 대답을 걸러냅니다. 각 언어와 프레임워크의 특징을 비교할 수 있는지 평가합니다.

✅ 모범 답변 가이드

Spring Boot React/Express

"Spring Boot로 팀 프로젝트를 진행하면서 훌륭한 백엔드 아키텍처를 경험했지만, 프론트엔드 화면 처리에 있어서 기존 템플릿 엔진(JSP, Thymeleaf)의 한계와 화면 깜빡임이 아쉬웠습니다."

"그래서 개인 프로젝트에서는 SPA(Single Page Application) 기반의 CSR(클라이언트 사이드 렌더링)을 깊이 있게 이해하고자 React를 선택했습니다. 또한, 프론트엔드에 집중하기 위해 백엔드는 자바스크립트로 동일하게 빠르게 구축할 수 있는 Node.js(Express) 환경을 도입하여, 서버 렌더링과 클라이언트 렌더링 환경의 차이를 명확하게 체감해 보고 싶었습니다."

Q.결제나 등록 버튼을 사용자가 두 번 이상 아주 빠르게 연속 클릭('따닥')했을 때 발생할 수 있는 문제는 무엇이고, 어떻게 해결할 수 있나요?

🎯 면접관의 의도

실제 서비스 운영 중 가장 많이 터지는 버그입니다. 프론트엔드에서의 방어 로직과 백엔드에서의 데이터 무결성 보장(멱등성) 경험을 묻습니다.

✅ 모범 답변 가이드

"따닥 클릭이 발생하면 백엔드로 API 요청이 두 번 날아가서 결제가 중복으로 되거나 게시글이 2개 작성되는 치명적인 데이터 정합성 문제가 발생할 수 있습니다."

"이를 해결하기 위해 프론트엔드와 백엔드 양방향에서 방어해야 합니다.
  • 프론트엔드: 클릭 시 버튼을 즉시 disabled(비활성화) 상태로 변경하거나, 디바운스(Debounce)나 쓰로틀링(Throttling) 함수를 적용해 짧은 시간 내의 중복 요청을 무시하도록 처리합니다.
  • 백엔드: 프론트엔드의 방어가 뚫릴 것에 대비해, DB 테이블에 Unique 제약조건을 걸거나 서버에서 트랜잭션 Lock을 걸어 동일한 요청(멱등성)에 대해서는 에러를 뱉도록 처리해야 합니다."

💬 Part 3. 실무 적응력 및 압박 질문 방어

Q.(압박 ⚠️) 우리 회사는 JPA를 주로 쓰는데, 포트폴리오를 보니 MyBatis만 써보셨네요. 입사하면 꽤 고생할 텐데 잘 대응할 수 있나요?

🎯 면접관의 의도

지원자의 RDBMS/SQL 기본기를 확인하고, 낯선 기술(JPA)에 대한 학습 태도와 자신감을 검증합니다. 기가 죽거나 변명하는 것을 주의해야 합니다.

✅ 모범 답변 가이드

(SQL 기본기를 어필하며 빠른 적응을 약속하세요!)
"네, 프로젝트에서는 MyBatis를 사용했습니다. 하지만 저는 이 과정에서 개발자가 직접 복잡한 SQL을 짜보고 조인(Join)과 쿼리 성능을 고민해 보았던 경험이 결코 헛되지 않다고 생각합니다."

"JPA가 객체 지향적으로 쿼리를 자동 생성해 주어 생산성이 높다는 것은 잘 알고 있습니다. 하지만 결국 그 내부에서 돌아가는 것은 RDBMS의 SQL입니다. 저는 MyBatis를 통해 SQL의 본질과 DB 동작 원리를 탄탄하게 다져놓았기 때문에, JPA가 만들어내는 쿼리를 누구보다 빠르고 정확하게 이해하고 튜닝할 수 있는 기반이 마련되어 있다고 자신합니다. 입사 확정 직후부터 곧바로 JPA 관련 도서를 학습하여 실무에 차질이 없도록 준비하겠습니다."

Q.코딩이나 IT를 전혀 모르는 비개발자(고객, 기획자)가 시스템에 문제가 생겼다며 상황을 설명할 때, 어떻게 소통하고 대처할 것인가요?

🎯 면접관의 의도

개발자의 '커뮤니케이션 스킬'을 묻습니다. 기술적 우월감에 빠지지 않고 상대방의 눈높이에 맞춰 문제를 파악하고 해결해 나가는 태도를 봅니다.

✅ 모범 답변 가이드

"가장 먼저 전문적인 IT 용어 사용을 배제하고 일상적인 언어로 소통하겠습니다."

"사용자는 내부 로직을 모르기 때문에 '서버 에러가 납니다' 대신 '저장 버튼을 눌렀는데 화면이 하얗게 변해요'처럼 눈에 보이는 현상 위주로 설명할 것입니다. 저는 '어떤 메뉴에서 어떤 버튼을 누르셨을 때 그런 현상이 발생했나요?'라고 구체적인 재현 스텝(Step)을 정중히 여쭤보겠습니다.
그리고 그분이 말씀해주신 정확한 시간대와 액션을 기반으로, 서버의 에러 로그(Log)를 추적하여 빠르고 정확하게 원인을 파악한 뒤 해결해 드리겠습니다."

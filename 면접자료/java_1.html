Q.Java의 객체지향 특징 4가지에 대해 본인의 언어로 설명해 주시겠어요?

🎯 면접관의 의도

단순히 암기한 내용을 읊는 것을 원하지 않습니다. 각 특징이 '유지보수와 코드 재사용'에 어떤 도움을 주는지 실무적인 관점이나 비유를 통해 이해하고 있는지 평가합니다.

✅ 모범 답변 가이드

네, 객체지향의 4대 특징은 캡슐화, 상속, 추상화, 다형성입니다.
  • 캡슐화: 외부에서 알 필요 없는 내부 로직을 숨기고, 접근 제어자(private)를 통해 데이터를 보호하는 것입니다. 약 먹을 때 캡슐 안의 가루약 성분을 몰라도 효능을 얻는 것과 같습니다.
  • 상속: 부모 클래스의 기능과 속성을 자식 클래스가 물려받아 코드를 재사용하는 것입니다. (단, 실무에서는 결합도가 높아져 상속보다는 '조합(Composition)'을 선호하는 추세라고 덧붙이면 플러스 점수!)
  • 추상화: 복잡한 시스템에서 핵심적인 개념이나 기능만 뽑아내어 인터페이스나 추상 클래스로 정의하는 것입니다.
  • 다형성 (가장 중요!): 하나의 객체가 여러 가지 타입을 가질 수 있는 성질입니다. 부모 타입의 변수로 다양한 자식 객체를 다룰 수 있어(Overriding), 코드 변경 없이 새로운 기능을 유연하게 추가할 수 있게 해줍니다.
#객체지향 #OOP #다형성

Q.(기출) 인터페이스(Interface)와 추상 클래스(Abstract Class)의 차이점은 무엇이고, 언제 각각을 사용해야 하나요?

🎯 면접관의 의도

두 개념의 문법적 차이(다중 상속 여부 등)를 아는지 확인하고, 나아가 '설계적 관점'에서 목적에 맞게 두 가지를 구분해서 쓸 수 있는지 묻는 단골 질문입니다.

✅ 모범 답변 가이드

가장 큰 문법적 차이는 '다중 상속' 여부입니다. 인터페이스는 다중 구현이 가능하지만, 추상 클래스는 단일 상속만 가능합니다. 하지만 설계적인 목적이 더 다릅니다.
  • 추상 클래스 ("~이다", IS-A): 부모와 자식이 밀접하게 연관되어 있고, 공통된 필드나 기능(일반 메서드)을 물려주어 코드 중복을 줄일 때 사용합니다. (예: Animal 추상 클래스와 Dog, Cat)
  • 인터페이스 ("~할 수 있는", HAS-A/CAN-DO): 서로 관련이 없는 클래스들이라도, "이 기능은 무조건 구현해야 해!"라는 규약(설계도)을 강제할 때 사용합니다. 다형성을 구현하는 핵심 도구입니다. (예: Flyable 인터페이스를 새와 비행기가 각각 구현)

Q.String과 StringBuilder, StringBuffer의 차이점은 무엇인가요?

🎯 면접관의 의도

자바의 메모리 구조(불변 객체)에 대한 이해도와, 성능을 고려하여 코드를 작성할 줄 아는지 평가합니다.

✅ 모범 답변 가이드

1. 불변성 (Immutability):
가장 큰 차이는 String은 불변(Immutable) 객체라는 점입니다. String에 '+' 연산으로 문자열을 합치면 기존 객체를 수정하는 것이 아니라, 새로운 객체를 메모리에 계속 생성하므로 성능 저하와 메모리 낭비가 심합니다.

2. 가변성 (Mutability):
반면 StringBuilder와 StringBuffer는 가변(Mutable) 객체입니다. 객체를 새로 만들지 않고 내부 버퍼를 이용해 문자열을 수정하므로 성능이 좋습니다.

3. 쓰레드 동기화:
StringBuffer는 멀티스레드 환경에서 안전하게 동작하도록 동기화(Synchronized)가 되어 있어 약간 느립니다. 반면 StringBuilder는 동기화가 없어서 단일 스레드 환경에서 가장 빠릅니다. 따라서 문자열 조작이 많을 때는 주로 StringBuilder를 사용합니다.
#불변객체 #메모리효율 #StringBuilder

Q.(기출 변형) ArrayList와 LinkedList의 차이는 무엇이고, 어떤 상황에서 ArrayList를 쓰는 것이 유리할까요?

🎯 면접관의 의도

자료구조의 기본 지식을 묻는 질문입니다. 데이터가 메모리에 어떻게 저장되는지 원리를 알고, 상황에 맞는 컬렉션을 선택할 수 있는지 확인합니다.

✅ 모범 답변 가이드

두 컬렉션은 데이터가 메모리에 저장되는 구조가 다릅니다.
  • ArrayList (조회에 유리): 데이터가 메모리에 연속적으로 나열되어 있습니다. 방 번호(인덱스)만 알면 한 번에 접근할 수 있어 데이터 조회가 매우 빠릅니다. 하지만 중간에 데이터를 삽입/삭제할 때는 뒤의 데이터들을 모두 밀거나 당겨야 해서 속도가 매우 느립니다.
  • LinkedList (삽입/삭제에 유리): 데이터가 흩어져 있고 서로 선(링크)으로 연결되어 있습니다. 중간에 데이터를 추가하거나 지울 때 선만 끊어서 다시 연결하면 되므로 삽입/삭제가 매우 빠릅니다. 하지만 특정 데이터를 찾으려면 처음부터 선을 따라가야 해서 조회가 느립니다.
결론적으로, 웹 서비스의 게시판 목록처럼 한 번 저장하고 '조회'를 압도적으로 많이 하는 상황에서는 ArrayList를 사용하는 것이 유리합니다.
#자료구조 #Collection #ArrayList

Q.Checked Exception과 Unchecked Exception의 차이는 무엇인가요? 스프링 트랜잭션과 연관 지어 설명해 줄 수 있나요?

🎯 면접관의 의도

에러가 났을 때 컴파일러가 강제하는지 여부를 아는지 확인하고, 실무(Spring)에서 트랜잭션 롤백 정책이 예외 종류에 따라 어떻게 달라지는지 묻는 약간 난이도 있는 질문입니다.

✅ 모범 답변 가이드

1. 컴파일 시점의 확인:
Checked Exception(예: IOException)은 컴파일러가 "너 이거 에러 날 수 있으니까 반드시 try-catch 하거나 throws로 던져!"라고 강제하는 예외입니다. 반면 Unchecked Exception(예: NullPointerException, RuntimeException)은 실행 도중(Runtime)에 발생하며 명시적인 처리를 강제하지 않습니다.

2. 스프링 트랜잭션(@Transactional)의 롤백:
스프링의 기본 설정상 Unchecked Exception(RuntimeException 하위)이 발생하면 자동으로 트랜잭션을 롤백(Rollback)합니다. 하지만 Checked Exception이 발생하면 기본적으로 롤백하지 않습니다. (만약 롤백시키고 싶다면 @Transactional(rollbackFor = Exception.class) 처럼 명시해 주어야 합니다.)
#예외처리 #Exception #Spring트랜잭션

Q.Java는 메모리 관리를 개발자가 직접 하지 않는데, 객체가 어떻게 메모리에서 지워지는지 (Garbage Collection) 설명해 볼래요?

🎯 면접관의 의도

JVM(Java Virtual Machine)의 동작 원리와 메모리 구조(Heap 영역)에 대한 기초 지식이 있는지 확인하는 단골 질문입니다.

✅ 모범 답변 가이드

Java 프로그램이 실행되면 생성된 객체들은 JVM의 힙(Heap) 메모리 영역에 저장됩니다.

이때 Garbage Collector(GC)는 주기적으로 힙 메모리를 돌면서, 더 이상 어떤 변수에서도 참조하고 있지 않은 'Unreachable(도달 불가능한)' 객체들을 찾아내어 메모리에서 자동으로 해제(청소)합니다.

덕분에 개발자가 수동으로 메모리를 비워주지 않아도 되어 생산성이 높아지고 메모리 누수(Memory Leak) 위험이 줄어듭니다.
#JVM #GarbageCollection #메모리구조

INTERVIEW PREP - PART 1

💛 JS 면접 시크릿 노트: 코어(Core) 편

단순한 DOM 조작을 넘어, 브라우저가 자바스크립트를 어떻게 해석하고 실행하는지 원리를 증명하세요.

Q.var, let, const의 차이점과 '호이스팅(Hoisting)'에 대해 설명해 주시겠어요?

🎯 면접관의 의도

모던 자바스크립트(ES6)의 기본 중의 기본입니다. 스코프(Scope)의 개념과 자바스크립트 엔진이 변수를 어떻게 메모리에 올리는지 동작 원리를 묻는 질문입니다.

✅ 모범 답변 가이드

1. 스코프(Scope)의 차이:
var는 함수 스코프를 가져서 의도치 않은 변수 값 변경이 발생하기 쉽습니다. 반면 let과 const는 블록 스코프({ })를 가져서 안전한 코드 작성이 가능합니다. (const는 재할당 불가)

2. 호이스팅(Hoisting):
자바스크립트 엔진은 코드를 실행하기 전에 선언된 변수들을 모두 스코프의 최상단으로 끌어올리는(Hoisting) 작업을 합니다.
  • var는 끌어올려지면서 undefined로 초기화되므로 선언 전에 호출해도 에러가 나지 않습니다.
  • 반면 let과 const도 호이스팅은 되지만, 초기화가 되지 않아 TDZ(Temporal Dead Zone, 일시적 사각지대)에 빠집니다. 따라서 선언 전에 호출하면 ReferenceError가 발생하여 더 안전합니다.
#Hoisting #스코프 #TDZ

Q.(기출) 자바스크립트에서 `this`는 상황에 따라 값이 변하는데, 어떻게 결정되는지 설명해 볼래요?

🎯 면접관의 의도

타 언어(Java 등)와 가장 크게 다른 JS만의 독특한 특징입니다. 실행 컨텍스트(Execution Context)와 화살표 함수(Arrow Function)의 존재 이유를 정확히 아는지 평가합니다.

✅ 모범 답변 가이드

자바스크립트에서 this는 함수가 선언될 때가 아니라, "함수가 호출되는 방식"에 따라 동적으로 결정됩니다.
  • 일반 함수 호출: 기본적으로 전역 객체(브라우저에서는 window)를 가리킵니다. (엄격 모드에서는 undefined)
  • 메서드 호출: 객체의 메서드로 호출될 때는, 메서드를 마침표(.) 기호로 호출한 그 객체 자체를 가리킵니다.
  • 생성자 함수 호출 (new): new 키워드로 호출 시 미래에 생성될 새로운 인스턴스(객체)를 가리킵니다.
  • 화살표 함수 (중요): 화살표 함수는 자신만의 this를 가지지 않고, 자신을 둘러싼 외부 환경(Lexical Context)의 this를 그대로 상속받습니다. 콜백 함수 등에서 this가 꼬이는 문제를 해결할 때 주로 씁니다.
#this #실행컨텍스트 #화살표함수

Q.(기출) 동기(Sync)식과 비동기(Async)식의 차이는 무엇인가요? 자바스크립트는 싱글 스레드인데 어떻게 비동기 처리를 하나요?

🎯 면접관의 의도

프론트엔드/백엔드 서버 통신(API 호출)의 핵심입니다. 이벤트 루프(Event Loop)의 개념을 곁들여 설명할 수 있다면 최고의 평가를 받습니다.

✅ 모범 답변 가이드

1. 동기와 비동기의 차이:
동기는 순차적으로 실행되며, 앞선 작업이 끝날 때까지 다음 작업이 멈춰서 기다리는(Blocking) 방식입니다. 반면 비동기는 오래 걸리는 작업을 던져놓고 즉시 다음 작업을 실행(Non-blocking)하는 방식입니다.

2. JS의 비동기 처리 원리 (이벤트 루프):
자바스크립트 자체는 스레드가 하나(Single Thread)라 한 번에 하나씩만 일합니다. 하지만 브라우저(또는 Node.js)가 멀티 스레드로 동작합니다.
비동기 작업(API 호출, setTimeout 등)을 만나면 자바스크립트는 이를 브라우저의 Web API로 넘겨버립니다. 처리가 완료되면 콜백 함수가 태스크 큐(Task Queue)에 담기고, 이벤트 루프(Event Loop)가 메인 스택이 비어있는지 확인한 뒤 콜백을 올려보내 실행하게 됩니다.
#동기비동기 #이벤트루프 #싱글스레드

Q.(기출) Local Storage와 Session Storage, 그리고 Cookie의 차이점과 각각 어떤 데이터를 저장할 때 쓰나요?

🎯 면접관의 의도

인증(JWT) 토큰이나 장바구니 데이터를 프론트엔드에서 어디에 저장해야 안전하고 효율적인지, 즉 '브라우저 저장소' 활용 능력을 검증합니다.

✅ 모범 답변 가이드

세 가지 모두 클라이언트(브라우저)에 데이터를 저장하는 방식입니다.
  • Cookie (쿠키): 용량이 작고(4KB), 서버로 API 요청을 보낼 때 HTTP 헤더에 자동으로 담겨 전송됩니다. 만료 기간을 설정할 수 있으며 주로 '오늘 하루 보지 않기' 팝업이나 서버 사이드 세션 ID 관리에 쓰입니다.
  • Local Storage: 용량이 크며(5MB), 브라우저를 종료해도 데이터가 영구적으로 유지됩니다. 자동 로그인 설정이나 사용자의 다크모드/라이트모드 설정 상태 등을 저장할 때 씁니다.
  • Session Storage: Local Storage와 비슷하지만, 브라우저나 해당 탭을 닫는 순간 데이터가 즉시 날아갑니다. 보안이 중요하거나 잠깐만 유지해야 하는 일회성 로그인 정보, 입력 폼 작성 중 임시 저장 등에 사용합니다.
#브라우저저장소 #LocalStorage #Cookie

Q.이벤트 버블링(Event Bubbling)에 대해 설명하고, 이를 활용한 '이벤트 위임(Event Delegation)' 기법이 무엇인지 아시나요?

🎯 면접관의 의도

DOM 이벤트를 얼마나 효율적으로 다룰 수 있는지 확인합니다. 게시판 리스트처럼 수십 개의 항목에 이벤트를 달아야 할 때 메모리를 낭비하지 않고 코드를 짤 수 있는지 평가합니다.

✅ 모범 답변 가이드

1. 이벤트 버블링:
특정 요소에서 클릭 같은 이벤트가 발생했을 때, 그 이벤트가 부모 요소를 타고 최상위 요소(document)까지 물거품(Bubble)처럼 뽀글뽀글 전파되는 현상을 말합니다.

2. 이벤트 위임(Event Delegation):
이 버블링 성질을 이용한 최적화 기법입니다. 예를 들어 100개의 <li> 버튼이 있을 때, 100개 각각에 이벤트 리스너를 달면 메모리 낭비가 심하고 동적으로 추가된 요소에는 이벤트가 작동하지 않습니다.
대신 부모 요소인 <ul>에 단 하나의 이벤트 리스너만 달아두고, 자식 요소에서 발생한 이벤트가 부모로 올라오면 event.target을 통해 어느 자식인지 식별하여 처리하는 방식입니다.
#EventBubbling #이벤트위임 #DOM최적화

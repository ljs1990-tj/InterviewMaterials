🗣️ Part 1. 인성 및 개발자 태도 (Fit)

Q.요즘 AI가 코드를 다 짜주는데, 본인도 혹시 생각 없이 복붙만 하는 '바이브 코딩'을 한 것은 아닌가요? (코드 본인이 직접 짰나요?)

🎯 면접관의 의도

비전공자나 국비 수강생들이 가장 많이 받는 압박 질문입니다. AI(ChatGPT 등)나 구글링에 의존하여 원리도 모르고 동작만 하게 만들었는지, 아니면 코드를 완벽히 통제하고 이해하고 있는지 '주도성'을 검증합니다.

✅ 모범 답변 가이드

솔직함과 검증 과정을 강조하세요.
"AI의 도움이나 레퍼런스를 참조한 것은 사실입니다. 하지만 절대 원리 모를 코드를 복사해서 붙여넣기만(바이브 코딩) 하지는 않았습니다.

제가 짠 코드가 아니더라도 반드시 한 줄 한 줄 주석을 달며 실행 흐름을 분석했고, 에러가 났을 때 AI에게 에러 로그만 던져주는 것이 아니라 제가 가설을 먼저 세우고 그 방향이 맞는지 확인하는 용도로만 도구를 활용했습니다. 그 결과 지금 당장 노트북이 주어져도 제 프로젝트의 핵심 기능은 백지에서 다시 짤 수 있습니다."

Q.우리 회사는 SI(또는 솔루션) 회사인데 본인은 어떤 성향이 더 잘 맞을 것 같나요? 파견(수도권)을 갈 수도 있는데 괜찮은가요?

🎯 면접관의 의도

회사의 비즈니스 모델(BM)을 이해하고 있는지, 그리고 업무 환경 변화에 대한 '적응력'과 '이탈률(퇴사 가능성)'을 평가합니다.

✅ 모범 답변 가이드

회사의 성향에 맞춰 긍정적인 태도를 어필하세요.
  • SI/파견 면접 시: "다양한 도메인과 환경을 겪어볼 수 있는 SI가 제 성장에 훨씬 큰 도움이 된다고 생각합니다. 새로운 고객사의 요구사항을 분석하고, 낯선 환경(파견)에서도 빠르게 적응하여 문제를 해결해 내는 것에 흥미를 느낍니다."
  • 솔루션 면접 시: "하나의 프로덕트를 깊이 있게 고도화하고, 코드의 품질을 높이며 장기적으로 서비스의 성장을 지켜볼 수 있는 솔루션 환경이 제게 잘 맞습니다."

Q.회사에 입사하고 나서 3개월짜리 개인 프로젝트를 주면 어떤 단계로 수행할 건가요?

🎯 면접관의 의도

단순히 코딩만 하는 '코더'가 아니라, 소프트웨어 공학적인 관점에서 기획-설계-구현-테스트의 '개발 라이프사이클(SDLC)'을 이해하고 일정을 관리할 수 있는지 묻습니다.

✅ 모범 답변 가이드

"먼저 무작정 개발부터 시작하지 않고, 전체 기간의 30% 이상을 요구사항 분석과 설계에 투자하겠습니다."
  • 1단계 (요구사항 분석 및 기획): 프로젝트의 핵심 목적을 파악하고, 사용자 시나리오와 요구사항 정의서를 작성합니다.
  • 2단계 (DB 및 아키텍처 설계): ERD를 그리고 API 명세서를 작성하여 데이터의 흐름을 뼈대부터 잡겠습니다.
  • 3단계 (개발): 핵심 비즈니스 로직부터 애자일(Agile)하게 우선순위를 두어 개발하고, 지속적으로 중간 점검을 하겠습니다.
  • 4단계 (테스트 및 배포): 단위 테스트를 거쳐 예상치 못한 버그를 잡고, 최종 산출물을 문서화하겠습니다.

💻 Part 2. 프로젝트 심층 분석

Q.개인/단체 채팅 기능을 구현했는데, 둘의 구현 방식(DB 설계나 로직)에 어떤 차이가 있었나요?

🎯 면접관의 의도

채팅이라는 흔한 포트폴리오 소재를 얼마나 깊이 고민하며 DB 모델링을 짰는지, 확장성을 고려했는지 압박하는 실무 질문입니다.

✅ 모범 답변 가이드

"가장 큰 차이는 '참여자(User) 관리 테이블'의 다대다(M:N) 매핑 구조였습니다."

"개인 채팅은 단순히 방 번호에 유저 A와 유저 B만 매핑하면 되지만, 단체 채팅은 유저가 수시로 들어오고 나갈 수 있기 때문에 Chat_Room(채팅방)과 User(사용자) 사이에 Chat_Member(참여자 매핑 테이블)을 두어 다대다 관계를 해소했습니다.
또한, 통신 모듈로는 주기적으로 요청을 보내는 Ajax Polling 대신 실시간 양방향 통신이 가능한 WebSocket(STOMP) 프로토콜을 사용하여 서버 부하를 줄였습니다."

Q.댓글 기능을 구현하셨는데, 그렇다면 '대댓글(계층형 댓글)'은 어떤 식으로 구현했나요?

🎯 면접관의 의도

자기 참조(Self-Join) 테이블의 개념과 부모-자식 관계의 데이터 구조를 제대로 설계할 수 있는지 묻는 질문입니다.

✅ 모범 답변 가이드

"대댓글 구현을 위해 자기 참조(Self-Reference) 설계를 활용했습니다."

"댓글 테이블(Reply) 컬럼에 parent_id(부모 댓글 번호)를 추가했습니다. 일반 댓글(최상위)은 parent_id가 NULL이고, 특정 댓글에 달린 대댓글은 부모 댓글의 PK 값을 parent_id로 가집니다.
화면에 뿌려줄 때는 쿼리에서 ORDER BY나 오라클의 경우 START WITH ~ CONNECT BY (계층형 질의)를 사용하여 부모 댓글 바로 아래에 자식 댓글이 정렬되도록 로직을 구성했습니다."

🌐 Part 3. 프론트엔드 및 웹 기초

Q.웹 페이지를 이동할 때 화면 깜빡임 없이 빠르게 이동하는 기술이 있던데, 그게 무엇인지 아나요? (SPA 란?)

🎯 면접관의 의도

전통적인 멀티 페이지 렌더링(JSP 등)과 모던 웹 프론트엔드(React, Vue)의 렌더링 방식 차이점(CSR vs SSR)을 정확히 이해하고 있는지 묻습니다.

✅ 모범 답변 가이드

"네, 바로 SPA (Single Page Application) 아키텍처와 AJAX(비동기 통신)를 활용한 CSR(Client-Side Rendering) 방식입니다."

"전통적인 방식은 페이지를 이동할 때마다 서버로부터 전체 HTML 화면을 통째로 다시 받아오기 때문에 화면이 깜빡입니다. 반면 Vue나 React 같은 SPA 환경에서는 최초 접속 시 전체 자바스크립트 파일을 한 번만 로드해 둔 후, 이후 페이지를 이동할 때는 서버로부터 순수한 JSON 데이터(API)만 비동기로 받아와서 브라우저(클라이언트)가 필요한 부분만 실시간으로 갈아 끼우기 때문에 앱처럼 빠르고 부드럽게 이동할 수 있습니다."

Q.Vue.js (또는 React)에서 사용해 본 훅(Hook)이나 컴포넌트 라이프사이클에 대해 설명해 주세요.

🎯 면접관의 의도

프론트엔드 프레임워크를 단순 복붙이 아니라 생명주기(LifeCycle)에 맞춰 데이터를 언제 불러와야 하는지 제어할 수 있는지 확인합니다.

✅ 모범 답변 가이드

(Vue.js 답변 예시)
"가장 많이 활용한 라이프사이클 훅은 created와 mounted입니다. created는 데이터(상태)는 초기화되었지만 아직 화면(DOM)에는 그려지지 않은 시점이라, 주로 백엔드 API를 호출해 초기 데이터를 세팅할 때 썼습니다. mounted는 화면이 완전히 그려진 후의 시점이라 특정 DOM 요소를 직접 조작하거나 외부 라이브러리를 연동할 때 활용했습니다."

(React 답변 예시)
"주로 함수형 컴포넌트에서 useEffect와 useState 훅을 사용했습니다. 특히 useEffect를 활용하여 의존성 배열(Dependency Array)을 비워두고 컴포넌트가 처음 마운트될 때 백엔드 API 데이터를 한 번만 불러오도록 제어했으며, 상태가 변경될 때마다 필요한 부수 효과(Side Effect)를 처리했습니다."

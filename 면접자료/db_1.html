💾 DB 면접 시크릿 노트: Core & SQL 편

오라클과 MySQL의 차이를 명확히 인지하고, 인덱스와 조인의 원리를 아는 탄탄한 기본기를 증명하세요.

Q.(기출) RDBMS(관계형 DB)와 NoSQL의 차이점은 무엇이며, 각각의 장단점을 설명해 주시겠어요?

🎯 면접관의 의도

데이터의 성격에 맞게 적절한 데이터베이스 패러다임을 선택할 수 있는 '아키텍처 설계 관점'을 묻는 단골 질문입니다.

✅ 모범 답변 가이드

1. RDBMS (MySQL, Oracle 등):
데이터를 2차원 테이블(행과 열) 형태로 저장하며, 엄격한 스키마(구조)와 테이블 간의 관계(Join)를 맺습니다.
- 장점: 데이터의 무결성(정확성)을 완벽하게 보장하며, 복잡한 통계나 트랜잭션 처리에 강합니다. (예: 금융, 결제 시스템)
- 단점: 구조 변경이 까다롭고, 트래픽이 몰릴 때 장비를 여러 대 늘리는 수평 확장(Scale-out)이 어렵습니다.

2. NoSQL (MongoDB, Redis 등):
정해진 스키마 없이 JSON이나 Key-Value 형태로 데이터를 유연하게 저장합니다.
- 장점: 데이터 구조를 언제든 쉽게 바꿀 수 있고, 서버를 늘려 데이터를 분산 저장하는 수평 확장이 매우 쉽습니다. (예: 실시간 채팅, 로그 수집)
- 단점: 데이터가 중복 저장될 수 있어 수정 시 일관성을 맞추기 어렵고 복잡한 JOIN 쿼리가 힘듭니다.
#RDBMS #NoSQL #데이터무결성

Q.(기출) 오라클(Oracle)과 MySQL을 모두 사용해 보셨는데, 실무 개발 관점에서 두 DB의 차이점이 무엇이었나요?

🎯 면접관의 의도

두 DB를 수박 겉핥기로 배운 것이 아니라, 쿼리를 짜면서 체감했던 문법적 차이와 DB의 성격을 스스로 고민해 보았는지 확인합니다.

✅ 모범 답변 가이드

엔터프라이즈급인 오라클과 오픈소스 기반인 MySQL은 문법과 기능에서 꽤 차이가 있었습니다.
  • PK(기본키) 생성: 오라클은 별도의 SEQUENCE 객체를 만들어 NEXTVAL로 번호를 땄지만, MySQL은 테이블 컬럼 자체에 AUTO_INCREMENT를 걸어 훨씬 간편하게 자동 증가를 구현할 수 있었습니다.
  • 페이징 처리: 게시판 페이징을 할 때 오라클은 ROWNUM을 사용해 인라인 뷰(서브쿼리)를 감싸야 해서 쿼리가 복잡했지만, MySQL은 LIMIT 0, 10 명령어 하나로 매우 직관적으로 처리할 수 있었습니다.
  • 성격: 대용량 데이터의 안정성과 복잡한 프로시저가 필요하면 오라클이, 가볍고 빠른 웹 서비스 개발에는 MySQL이 적합하다고 느꼈습니다.
#Oracle #MySQL #Sequence_vs_AutoIncrement

Q.(기출) DB에서 조인(Join)을 사용할 때, Inner Join과 Outer Join(Left/Right)의 차이점은 무엇인가요?

🎯 면접관의 의도

가장 기본적인 SQL 작성 능력을 묻습니다. 벤 다이어그램의 '교집합'과 '합집합' 개념을 이해하고 데이터 누락을 방지할 수 있는지 평가합니다.

✅ 모범 답변 가이드

두 테이블을 합칠 때 '일치하지 않는 데이터'를 어떻게 버릴 것이냐 살릴 것이냐의 차이입니다.
  • Inner Join (내부 조인): 두 테이블 간에 조인 조건이 완벽히 일치하는 데이터(교집합)만 가져옵니다. 예를 들어, '부서가 없는 신입사원'은 결과에서 아예 누락되어 사라집니다.
  • Left Outer Join (외부 조인): 왼쪽 테이블의 모든 데이터를 무조건 살린 채로 오른쪽 테이블을 붙입니다. 부서가 없는 신입사원도 화면에 정상적으로 출력되며, 부서 정보 칸에는 NULL 값이 채워지게 됩니다. (데이터 누락을 방지하기 위해 실무에서 가장 많이 씁니다.)
#JOIN #InnerJoin #LeftOuterJoin

Q.(기출) 데이터베이스에서 인덱스(Index)란 무엇이며, 어떤 원리로 검색 속도가 빨라지나요? 무조건 인덱스를 많이 거는 것이 좋을까요?

🎯 면접관의 의도

쿼리 튜닝의 시작점입니다. 인덱스의 자료구조(B-Tree) 원리를 아는지, 그리고 인덱스의 '치명적인 단점(Trade-off)'을 이해하여 무분별한 사용을 피할 줄 아는지 확인합니다.

✅ 모범 답변 가이드

1. 인덱스의 개념과 원리:
인덱스는 두꺼운 전공 서적 맨 뒤에 있는 '찾아보기(색인)'와 같습니다. 테이블을 처음부터 끝까지 다 뒤지는 것(Full Scan)이 아니라, 트리(B-Tree) 구조로 미리 정렬해 둔 색인을 타기 때문에 조회(SELECT) 속도를 비약적으로 높여줍니다.

2. 무조건 많이 걸면 안 되는 이유 (단점):
인덱스도 결국 하드디스크 공간을 차지하는 '또 다른 테이블'입니다. 따라서 데이터가 새롭게 INSERT, UPDATE, DELETE 될 때마다 원본 테이블뿐만 아니라 인덱스 테이블까지 같이 정렬하고 갱신해주어야 합니다.
조회 속도는 빨라지지만 데이터 변경 속도는 오히려 느려지므로, 조회가 빈번한 컬럼에만 전략적으로 걸어주어야 합니다.
#Index #B-Tree #조회성능튜닝

Q.데이터베이스의 트랜잭션(Transaction)이란 무엇인가요? '계좌 이체' 상황을 예로 들어 설명해 주세요.

🎯 면접관의 의도

데이터의 무결성과 일관성을 지키기 위한 핵심 개념인 ACID 특성 중 '원자성(Atomicity)'을 실생활 비유로 완벽히 설명할 수 있는지 확인합니다.

✅ 모범 답변 가이드

트랜잭션은 '더 이상 쪼갤 수 없는 하나의 논리적 작업 단위'를 말합니다. 이 작업들은 "모두 완벽하게 성공(Commit)하거나, 아니면 아예 모두 실패한 상태(Rollback)로 되돌아가야 한다"는 원칙(원자성)을 가집니다.

[계좌 이체 예시]
A가 B에게 1만 원을 보낼 때, 1) A의 통장에서 1만 원을 뺀다. 2) B의 통장에 1만 원을 더한다. 이 두 쿼리는 무조건 하나의 트랜잭션으로 묶여야 합니다.
만약 A의 돈만 빠져나간 상태에서 서버가 다운(에러)된다면, 돈이 증발하는 대형 사고가 발생합니다. 트랜잭션을 걸어두면 에러 발생 시 즉시 ROLLBACK을 수행해 A의 돈을 원래대로 복구시킴으로써 데이터의 안전성을 보장합니다.
#트랜잭션 #Commit_Rollback #ACID

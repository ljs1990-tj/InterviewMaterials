🌱 Spring 면접 시크릿 노트: DB & MyBatis

프로젝트에서 다룬 MyBatis의 동작 원리를 증명하고, JPA와의 차이점을 아는 '생각하는 개발자'임을 어필하세요.

Q.프로젝트에서 MyBatis를 사용하셨는데, 최근 많이 쓰이는 JPA(ORM)와의 차이점이 무엇인지 알고 계신가요?

🎯 면접관의 의도

JPA를 안 써봤더라도 두 기술의 패러다임 차이(SQL 중심 vs 객체 중심)를 인지하고 있는지 묻는 1순위 단골 질문입니다.

✅ 모범 답변 가이드

가장 큰 차이는 '개발자가 직접 SQL을 짜느냐, 프레임워크가 짜주느냐'의 차이입니다.
  • MyBatis (SQL Mapper): 개발자가 직접 복잡한 SQL 쿼리를 작성하여 XML이나 어노테이션에 자바 객체와 매핑하는 방식입니다. 직접 통제권이 있어서 복잡한 통계 쿼리나 세밀한 DB 튜닝을 할 때 매우 유리합니다. (그래서 프로젝트의 성격에 맞게 선택했다고 어필하면 좋습니다.)
  • JPA (ORM 기술): 자바 객체(Entity)와 DB 테이블을 직접 매핑합니다. 기본적인 CRUD SQL을 프레임워크가 자동으로 생성해주어 생산성이 높고 완벽한 객체지향적 코드 작성이 가능합니다. 단, 러닝 커브가 높고 복잡한 쿼리를 짤 때는 별도의 기술(QueryDSL 등)이 필요합니다.
#MyBatis #JPA #SQL_Mapper #ORM

Q.MyBatis의 XML 매퍼에서 파라미터를 넘길 때 #{}와 ${}의 차이는 무엇이고, 보안상 어떤 이슈와 연관이 있나요?

🎯 면접관의 의도

보안에 취약한 주니어 개발자를 걸러내기 위한 가장 치명적인 질문입니다. SQL 인젝션(SQL Injection) 공격의 원리와 PreparedStatement의 개념을 묻습니다.

✅ 모범 답변 가이드

1. #{} (PreparedStatement 바인딩):
파라미터가 ?로 치환된 후, 입력값이 안전하게 바인딩되어 문자열인 경우 자동으로 양쪽에 따옴표(' ')가 붙습니다. 입력값이 순수한 데이터로만 취급되므로 SQL Injection 공격을 원천 차단합니다. 무조건 이 방식을 써야 합니다.

2. ${} (문자열 치환):
입력한 값이 쿼리 문장에 문자열 그대로(Statement) 삽입됩니다. 사용자가 ' OR 1=1 -- 같은 악의적인 코드를 넣으면 그대로 쿼리의 일부로 동작하여 DB가 털리게 됩니다. 테이블명이나 컬럼명 자체를 동적으로 바꿔야 하는 아주 제한적인 상황에서만 조심해서 사용해야 합니다.
#MyBatis_파라미터 #SQL_Injection방어 #PreparedStatement

Q.스프링에서 @Transactional로 트랜잭션을 관리할 때, 어떤 상황에서 자동으로 롤백(Rollback)이 발생하나요?

🎯 면접관의 의도

이전 Java 면접의 '예외처리' 질문과 연결되는 내용입니다. 스프링 AOP 기반 트랜잭션의 기본 동작 방식과 예외(Exception) 계층 구조를 묶어서 이해하고 있는지 평가합니다.

✅ 모범 답변 가이드

스프링의 @Transactional은 AOP 프록시를 통해 동작하며, 메서드 실행 도중 예외가 발생하면 롤백 여부를 결정합니다.

기본 설정상 런타임 예외(Unchecked Exception, 예: NullPointerException, RuntimeException)가 발생했을 때만 자동으로 롤백됩니다.

반면, 파일 입출력 등 컴파일러가 강제하는 Checked Exception(예: IOException, SQLException)이 발생하면 기본적으로 롤백되지 않고 커밋을 시도합니다. 따라서 모든 예외에서 롤백시키려면 @Transactional(rollbackFor = Exception.class) 속성을 명시해주어야 안전합니다.
#@Transactional #Rollback정책 #RuntimeException

Q.Spring Boot는 데이터베이스와 통신할 때 내부적으로 HikariCP라는 '커넥션 풀(Connection Pool)'을 사용합니다. 이를 사용하는 이유는 무엇일까요?

🎯 면접관의 의도

DB와 서버 간의 물리적 통신 비용을 알고 있는지, 대규모 트래픽을 처리하는 백엔드 서버의 성능 최적화 기본기를 묻는 질문입니다.

✅ 모범 답변 가이드

애플리케이션이 DB와 통신하기 위해 매번 네트워크 연결(3-Way Handshake)을 맺고 인증을 거치는 과정은 CPU와 메모리, 시간을 엄청나게 잡아먹는 무거운 작업입니다. 요청이 들어올 때마다 커넥션을 생성하면 서버가 버티지 못합니다.

그래서 애플리케이션 시작 시점에 미리 일정 개수의 커넥션을 만들어 풀(Pool)이라는 공간에 보관해 둡니다. 클라이언트의 요청이 오면 만들어둔 커넥션을 빌려주고, 쿼리 실행이 끝나면 다시 풀에 반납받아 재사용함으로써 응답 속도를 획기적으로 높이고 DB의 과부하를 막는 것입니다. (스프링 부트는 가장 성능이 좋은 HikariCP를 기본으로 채택하고 있습니다.)
#HikariCP #ConnectionPool #성능최적화

Q.(기출) 백엔드 개발 시 DAO, DTO, Entity(Model)를 나누어 사용하는 이유는 무엇인가요?

🎯 면접관의 의도

계층형 아키텍처(Controller - Service - Repository)에서의 역할 분리와 데이터 전송 객체의 필요성을 명확히 아는지 확인합니다.

✅ 모범 답변 가이드

각 객체는 계층 간 역할 분리를 위해 명확한 목적을 가지고 나눠서 씁니다.
  • Entity (Model): 실제 DB 테이블 구조와 1:1로 매핑되는 핵심 객체입니다. DB와 맞닿아 있으므로 화면 요구사항이 바뀐다고 해서 이 객체를 함부로 수정해선 안 됩니다.
  • DTO (Data Transfer Object): Controller와 클라이언트(화면) 간에 데이터를 주고받기 위한 '택배 상자'입니다. 비즈니스 로직 없이 getter/setter만 가지며, 화면에서 요구하는 폼 데이터 구조에 맞춰 자유롭게 변형하여 사용합니다.
  • DAO (Data Access Object / Mapper): DB에 직접 접근하여 SQL을 실행하고 데이터를 가져오거나 조작하는 역할을 하는 통로입니다. (MyBatis의 @Mapper 인터페이스가 이 역할을 수행합니다.)
#DTO_DAO_Entity #계층형아키텍처 #관심사분리
